# 브랜치 가이드 (branch-guide)

이 저장소의 git 브랜치 모델과 **실행 모드**(기본/자율)를 규정한다. 기본·자율 실행에 동일하게 적용된다.

## 브랜치 모델

```
main   ← baseline (보호 — 직접 커밋/push 금지, 훅이 차단)
  └── dev   ← integration (보호 — 직접 커밋/push 금지, 훅이 차단)
        ├── feature/{이슈번호}-{기능}   ← 작업 1 (커밋·push·PR 여기서)
        ├── feature/{이슈번호}-{기능}   ← 작업 2
        └── ...   각 작업 → PR(base: dev) → 사람 검토 → merge
```

## 네이밍 규칙

- 모든 작업 브랜치: **`feature/{이슈번호}-{기능}`** (예: `feature/12-create`, `feature/15-search`)
  - 이슈 번호로 브랜치·PR·이슈를 연결한다 (`docs/workflow/issue-pr-guide.md`).
- **기본·자율 실행 동일** — 이름은 "모드"가 아니라 "작업"으로 짓는다. 모두 **`dev`에서 분기**한다.

## 보호 규칙 (main · dev)

- **`main`·`dev`에는 직접 커밋/push 금지.** 두 브랜치는 **PR merge로만** 갱신한다.
  - `feature/…` → PR(base: `dev`) → 사람 검토·merge → `dev`.
  - `dev`가 안정되면 사람이 `dev` → `main`을 정리한다.
- **feature 브랜치**에서는 커밋·push·PR을 자유롭게 한다.
- 강제 수단(git 훅, `.harness/hooks/`):
  - `pre-commit` — `main`·`dev` 직접 커밋 차단.
  - `pre-push` — `main`·`dev`로의 push 차단 (feature push는 허용).
  - 훅은 `.git/hooks/`에 있어 커밋·클론되지 않는다. 새 클론에선 `sh .harness/hooks/install.sh`로 재설치한다.
  - (부득이 우회: `git commit/push --no-verify`)

## 작업 흐름

```
1. dev에서 feature/{이슈번호}-{기능} 브랜치(기본) 또는 워크트리(자율) 생성
2. 그 브랜치에서 작업 (Plan → Generate → Evaluate)
3. 완료 → 커밋(기능 단위) → push → PR(base: dev)
4. 사람이 검토·merge → dev 갱신 (이후 dev → main은 사람이 정리)
```

> 이슈 생성·PR·검토 루프의 세부는 `docs/workflow/issue-pr-guide.md`.

## 실행 모드 (기본 vs 자율)

실행 방식은 두 가지이며, 각 문서의 **게이트 규칙은 기본 모드에만** 적용된다. **모든 작업은 `dev`에서 시작**하고, 격리 방식만 모드마다 다르다.

| 모드 | 게이트 | 격리 | 진입점 / 브랜치 생성 |
|------|--------|------|----------------------|
| **기본(gated)** | 계획 승인 + PR 검토(사람) | 브랜치 (메인 폴더, 순차) | 메인 에이전트가 `git switch -c feature/{작업} dev` |
| **자율(autonomous)** | 게이트 **생략** (사후 검토·테스트·루프 상한으로 대체) | 워크트리 (별도 폴더, 병렬) | 런처 `sh .claude/workflows/run-autonomous.sh {작업}` |

- **기본 모드**: `feature/…`에서 순차로 진행하고, PR을 올린 뒤 **사람 검토를 기다린다**(merge는 사람만).
- **자율 모드**: 작고 신뢰되는 작업 전용. 휴먼 게이트를 의도적으로 생략하고 Plan→Generate→Evaluate→(통과 시)Finalize를 쭉 실행한다. **명시적으로 워크플로우를 호출할 때만** 발동한다.
  - **진입점 = 런처**: 자율은 무조건 워크트리 세션 안에서 실행된다. 런처가 `dev`에서 워크트리(`../{저장소}-{작업}`)+브랜치(`feature/{작업}`)를 만들고 **그 안에서 `claude`를 띄워** 워크플로우를 실행한다 → 세션 폴더가 곧 워크트리라 권한 프롬프트가 없다.
  - **역할 분리**: 워크트리 생성·기동은 **런처**, 워크플로우 첫 단계 **Guard는 "워크트리 세션인지 검증"만** 한다(런처를 안 거치고 메인에서 직접 부르면 중단하고 런처로 안내).
  - **Finalize**: Evaluate 통과 시 `feature/{작업}` 브랜치에 자동 커밋 후 push+PR까지 진행한다(merge는 사람). 미통과(최대 3회)면 커밋하지 않고 워크트리에 남겨 사람이 검토한다.

> "승인 전엔 진행 금지"(기본)와 "게이트 없이 진행"(자율)은 **서로 다른 모드**라 충돌이 아니다.
> 브랜치 이름은 같고(`feature/…`) **격리만** 다르다 (기본=브랜치 순차 / 자율=워크트리 병렬).
